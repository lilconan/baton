# doc-humanize: 문서 한 개만 사람 글로 고치기

## 지키는 것 (어기면 덮어쓰지 않는다)

- **대상은 사용자가 말한 파일 하나다.** 경로가 없으면 직전에 만든 산출물을 후보로 말하고 확인받는다. 다른 파일은 열어 보기만 하고 고치지 않는다.
- **원문 인용은 한 글자도 바꾸지 않는다** (CLAUDE.md 규칙 7). 인용 ID, 링크, 코드, 숫자, 표 행 수, 제목 수도 그대로다. `tools/humanize_guard.py verify`가 통과해야만 덮어쓴다.
- **내용을 더하거나 빼지 않는다.** 문체·리듬·표현만 바꾼다. 쉬운 말 단계의 풀어 쓰기는 예외로, 용어 사전에 있는 뜻만 붙인다.
- 원본은 덮어쓰기 전에 `_workspace/{run_id}/original.md`로 남긴다.

## 절차

`{run}` = `_workspace/{YYYY-MM-DD}-doc-{파일명 앞 12자}` (repo 루트 기준, `_workspace/`는 .gitignore 대상)

1. **전 상태 측정**
   ```bash
   mkdir -p {run}
   hanlint "{파일}" | head -3          # 지적 수 기록
   cp "{파일}" {run}/original.md
   ```
2. **보호 대상 가리기**
   ```bash
   python3 tools/humanize_guard.py mask "{파일}" --run-dir {run}
   ```
   `{run}/masked.md`에서 인용·ID·링크·코드는 `⟦P001⟧` 같은 자리표시자가 된다.
3. **처음 읽는 사람 검사 (주 단계)**: 이 흐름의 목표는 "처음 보는 사람이 문장 하나만 읽고 뜻을 안다"이다.
   AI 티 엔진은 이 목표를 재지 않는다. 비유 동사와 조어를 핵심 내용어로 보고 오히려 보존한다. 그래서 이 검사를 먼저 한다.
   - 대화 맥락을 주지 않은 서브에이전트(general-purpose)에게 **원본 파일만** 읽힌다. 프롬프트에 이 대화의 배경, 기획 용어 설명, 내가 의도한 뜻을 넣지 않는다.
   - 문장마다 받는 표: `| 줄 | 문장 | 혼자 읽히나(예/대충/아니오) | 막히는 낱말·연결 | 혼자 서는 대안 문장 |`
   - 판정 기준을 함께 준다: korean-copy-guardrail의 "읽히는 문장 6"(행위자 주어, 세는 대상, 비유 동사, 문단 첫 문장의 지시어, 수치 주장 한 문장, 조어·템플릿 문구)
   - 인용문(큰따옴표 안)과 표의 숫자 칸은 판정 대상에서 뺀다.
   - "대충"·"아니오" 문장만 `{run}/masked.md`에서 다시 쓴다. 대안 문장을 그대로 붙이지 않고, 새로 넣는 행위자·대상은 **같은 문서나 근거 문서에 이미 있는 사실**일 때만 쓴다. 없는 사실이 필요하면 고치지 않고 보고한다.
   - 결과를 `{run}/clear.md`로 저장하고, 판정 표는 `{run}/coldread.md`로 남긴다.
4. **AI 티 마무리**: `humanize-korean:humanize-korean` 스킬을 `{run}/clear.md` 본문으로 실행한다.
   - 엔진에 함께 전할 조건: "`⟦P숫자⟧` 자리표시자는 글자 하나도 바꾸거나 지우거나 옮기지 말 것. 마크다운 표의 칸 구조와 제목 줄은 유지할 것. 3단계에서 풀어 쓴 실제 행동 동사를 다시 비유 동사로 바꾸지 말 것."
   - 결과(엔진의 `_workspace/.../final.md`)를 `{run}/humanized.md`로 복사한다. 엔진이 붙인 `<!-- HUMANIZE-SUMMARY -->` 블록은 떼어 `{run}/summary.md`로 옮긴다.
5. **쉬운 말 단계** (`output/` 아래 문서만 기본 적용, `docs/`는 사용자가 원할 때만)
   - `glossary.md`의 용어가 문서에서 **처음** 나오는 자리에만 풀이를 붙인다. 두 번째부터는 그대로 둔다.
   - 풀이는 괄호나 짧은 앞말로 붙이고, 원래 용어는 지우지 않는다(근거 문서와 대조할 수 있어야 한다).
6. **되돌리기와 검증**
   ```bash
   python3 tools/humanize_guard.py unmask {run}/humanized.md --run-dir {run} --out {run}/restored.md
   python3 tools/humanize_guard.py verify "{파일}" {run}/restored.md
   ```
   - `unmask`가 사라진 자리표시자를 보고하거나 `verify`가 실패하면 **덮어쓰지 않는다.** 무엇이 바뀌었는지 사용자에게 보여 주고, 해당 문단만 원문으로 되돌린 뒤 다시 검증한다.
   - 예외: `verify`는 글쓴이가 자기 문장에 붙인 따옴표(예: `"차별 지점"`, 표 칸의 `"…는 틀로 답함"`)도 인용으로 본다. 3단계에서 이런 문구를 고쳤다면 실패 목록을 한 줄씩 보고, **출처가 있는 인용(리뷰·커뮤니티·보도자료 원문)이 하나도 없을 때만** 진행한다. 보고에 "보호 검사에서 걸린 N곳은 모두 글쓴이 문구"라고 목록과 함께 적는다. 숫자·표 행·제목 수 실패는 예외 없이 멈춘다.
7. **덮어쓰기**: 검증을 통과한 `{run}/restored.md`를 원래 경로에 복사한다.
8. **다시 검사**: 덮어쓴 파일로 3단계 처음 읽는 사람 검사를 한 번 더 돌려 "대충·아니오" 문장 수를 센다.
9. **보고** (대화 답변)
   - 처음 읽는 사람 검사의 "대충·아니오" 문장 수 전 → 후 (이 흐름의 주 지표)
   - hanlint 지적 수 전 → 후, 엔진 게이트 변경률(엔진 출력값 그대로), 보호 대상 수
   - 바뀐 대표 문단 2~3개를 전/후로 보여 준다
   - 원본 백업 경로(`{run}/original.md`)와 되돌리는 방법(`cp {run}/original.md "{파일}"`)

## 쓰지 않는 것

- 외부 윤문 MCP(WriteHuman·ToHuman·Undetectable): 원문이 외부로 나가고, 목적이 탐지기 우회다.
- 다중 번역 파이프라인: 의미가 흔들리고 인용이 바뀐다.
- 대화 답변에는 이 흐름을 쓰지 않는다. 대화는 쓰는 단계에서 fluent-korean 출력 스타일과 korean-copy-guardrail 기준을 따른다.
